Create a new shared task in the team's task list.
Tasks track work items across the team and can have assignees, dependencies, and metadata.
Create shared tasks for multi-step work and assign owners before implementation starts.
Use dependency_ids when one task needs another task's result; leave dependencies empty for independent work.
Dependency tasks must complete before dependent tasks can be claimed.
Creating a task records tracking state only; it does not start or wake a teammate.

Exact-file reservations (owned_paths):
Pass owned_paths to exclusively reserve exact file paths for this task. Each path is canonicalized; a path already reserved by another task rejects the whole create. An owned task binds its owner only when a teammate claims it with team_task_claim (do not pass assignee for owned tasks). The owner may complete the task; the owner or the lead may cancel it. Completion of an owned task requires a structured handoff (see team_task_update); cancellation releases reservations without a handoff. Reservations are released on completion or cancellation and kept for audit. Reservations cover exact files through write, edit, and apply_patch inside one running project instance only; shell, plugin, MCP, formatter, external-process, and cross-process writes are not runtime controlled. Directory and glob claims are not supported yet; reserve exact files only.
